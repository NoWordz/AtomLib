# AtomDefault 与 AtomChat 反哺实施方案

> 状态：方案待确认；本次只授权编写方案和将 AtomLib 工作区版本升为 0.2.0。下述功能、AtomChat 修改、提交、发布和部署均未因此自动获准。AtomChat 正在并行开发，实施前重新固定两仓提交与工作区状态；不得覆盖并行工作。

**目标：**将 AtomChat 已验证的视觉、交互和性能经验整理成 AtomLib 可复用能力，以 AtomDefault 提供默认外观，并让 AtomChat 不因 Lib 版本号本身阻止使用其他版本。

**架构：**保留现有 Skija / Yoga / PresentationFrame 和可选 controls；视觉数据、动效、宿主业务和渲染资源各自持有状态。默认包提供通用外观和多套配色，旧公开 API 先保留兼容；不将聊天业务、导航栈、全局单例或第三方模组适配硬塞进通用核心。

**技术基线：**公共 Java 17；Forge 1.20.1 / JDK 17、Fabric 与 NeoForge 1.21.1 / JDK 21；Skija 0.143.18、现有 LWJGL Yoga。玩家端原生支持 Windows x64 / ARM64；本次未扩展平台。

## AtomChat 性能证据及反哺优先级（2026-11-02）

以下是仓内记录，不是本轮新跑的基准。`docs/verification/2026-11-02-render-quality-and-caching.md` 记录的真机面板基线为 panel p50 4.6ms / p95 9.1ms、每次约 95–190KB 分配；另一个离屏 A/B 在 500 条消息、中段滚动、200 次采样下，p50 2.191→1.313ms，分配 200.7→33.1KB/帧。50 条消息的 p50 为 1.459→1.389ms，记录认为落在噪声范围内。两者测试对象不同，不可相减或把离屏改善换算成实机 FPS。原临时 A/B bench 已删除，历史数字可查但不能一键复跑；新 benchmark 必须保留输入构造、运行命令、基线版本、采样和统计方式。

| 项目 | 已有优点 | 本次可确认的限制 / 后续行动 |
| --- | --- | --- |
| 消息列表 | `2a25c5a3` 通过稳定快照、完整失效键和行偏移复用减少重复测量；短列表保留噪声对照。 | 缓存思路可用于 Lib；消息 ID、表情、聊天折叠等业务键留宿主。仍须评估变更、宽度、字号、字体和资源代际对失效的影响，不称完整虚拟列表或实机 FPS 改善。 |
| 点阵装饰 | `DotTexture.drawEdge` 复用 paint，按条宽计算列数，记录了明确绘制位置，便于量化。 | 600 逻辑 px 条约 120 列 × 9 行；交接将三处相加约 3240 次，但根页面绘制底栏后返回，输入栏属于聊天详情，通常不是三处同一帧同时出现；halo、trail 等还会增量绘制。按页面、实际条宽、可见性与调用次数测 CPU/GPU，不能把该推算当实测瓶颈或本轮提交导致的回归。它是 AtomChat 自有装饰，不直接移入 Lib。 |
| 图片预处理 | 按缩小倍率选择是否生成派生图，限制派生像素及每源层数，并在资源重载释放。 | `7f9aa424` 之前与之后的门槛不同；2× 或 3× 都只是各自场景的候选，不是通用真值。源尺寸、首次 CPU 成本、采样质量、内存、淘汰和像素画模式必须同测；原交接未证实 GPU 收益。 |
| 缓存与生命周期 | 原生图片缓存设上限、清空或淘汰时 close；屏幕关闭释放部分资源。 | 复制思路而非静态全局缓存；先核对源/派生图和 paint 的持有关系及所有权。`ImageQuality.scaledFor` 插入后先执行总预算裁剪再返回新图，遍历可能先淘汰新图；例如 4096×4096 源图、目标宽 1100 会产生 2200×2200 派生图，超过 4M 像素预算且可能被裁剪关闭后返回。日常图片加载通常有较低上限，本次未证明实际界面可触发，也未动态复现。弱引用来源死亡后，派生图及条目只在同桶再访问、超预算裁剪或 reload 时清理，预算不限制空桶数量；长期增长速率待测。 |
| 字体缓存 | 回退字体条目数有上限，主字体字形命中缓存按字体实例区分。 | AtomChat 的文字宽度缓存仍按字号和文本共享，源码明确承认同字号 regular/bold 可能混用宽度；回退字体缓存淘汰未显式关闭，且存在借用字体，不能一律 close。Lib 不照搬这两个合同，需以字体身份 / 字重 / 资源代际键控并明确借用与所有权。 |
| Lib 色彩计算 | 现有 `hairline(int)` 可按背景纯函数选择明暗色，便于比较缓存前后输出。 | `hairline` 经 `Design.isLight` 可能调用 `Math.pow`；`cardFill(DesignHost)` 本身只计算 alpha 和 RGB，不能笼统说它每次都算亮度。先度量真实调用频次和收益，再按不可变主题快照或输入值缓存，保证多宿主隔离和主题切换立即失效。 |
| 局部绘制与画质 | 可利用设备像素探针和既有逐帧结果核对描边。 | 文字阴影的性能与锐度影响仍是待测假设；移除阴影前需对明暗主题可读性进行 A/B。静止整屏缓存涉及主题、缩放、背景、滚动、悬停、动画与输入失效，作为后续独立高风险议题。 |

## 待确认的决策

1. **兼容策略**：按用户要求，推荐编译输入继续固定版本与摘要；玩家运行时不按 Lib 版本号做精确匹配或人为设置版本上限，而验证 AtomChat 实际需要的能力。候选方案 A 是只取消版本门禁，改动小但缺少 API 时可能晚崩；方案 B 是取消版本门禁并在客户端启动时对必需 API / 资源做能力检查，缺失时报告具体原因，推荐 B。任意版本可通过版本号检查不等于任意版本的 API 都能工作；目标 MC、加载器、客户端和 native 平台约束仍有效。能力检测的范围和成本在设计确认时定案。
2. **重命名**：A. 直接删除 `design.atomchat`，破坏已有二进制；B. 推荐增加 `design.atomdefault` 新入口并保留旧包兼容，检查源码和二进制消费者、静态状态和类型身份；C. 只改文档显示名，无 API 改善。兼容层的生命周期与弃用时机另定，不能仅复制一套全局状态。
3. **预设**：推荐参考 AtomChat 的 12 套颜色预设，以不可变语义配色表达共用面板、卡片、主次文字、强调色、描边；聊天气泡和业务持久化留给宿主。现有默认外观保留为可选基线；具体哪一套作为默认、亮暗主题对比和细节观感由用户选择 / A/B 验收。
4. **Dango 借鉴深度**：推荐吸收即时绘制、局部状态归属、可中断动效、简洁的绘制上下文思想；不因此重写成 Kotlin、替换 Yoga 或再造 UI 树。实际表达和素材先过来源审计。

- [ ] 对拟迁移的主题、动画、图片、探针逐项记录源文件、提交、许可证、许可依据和处置。对 `UiStagger`、相关弹簧改动和 Dango 的相似实现单独核对；无法闭合的项仅记录行为合同，不复制表达。

### 2. AtomDefault 样式与预设

**候选文件：**`ui/src/main/java/com/atom/lib/design/atomdefault/` 下的不可变主题、预设、皮肤入口；现有 `design/atomchat/` 的兼容门面；`ui/src/test/java/com/atom/lib/design/` 下跨宿主测试；`docs/design-package.md`、`docs/controls.md`、示例与迁移文档。

- [ ] 建立不可变样式快照；每个 `ControlContext` / skin 使用自己的实例，主题切换不能改变另一个宿主。预设包含语义颜色与必要材质参数，不包含聊天存储、配置路径和业务动作。
- [ ] 依据 AtomChat `ThemeService` 逐项核对 12 套色值、透明度及明暗文字对应关系；记录未映射的业务字段。旧 `AtomChatControlStyle` 和相关公开构造方式继续可用。
- [ ] 用真实旧版编译消费者在新 jar 上运行，检查旧包、类、方法、字段和共享状态；两宿主交错绘制时颜色、ripple、字体角色互不串扰。视觉覆盖至少一明一暗，生成可供用户 A/B 的结果，数值不能自定为观感通过。

### 3. 动效与交互

**候选文件：**`core/.../motion/SpringAnim.java`、`ui/.../controls/Control.java`、`ui/.../controls/ControlMotion.java`、默认皮肤与对应测试；若需通用入场模型，新增归属清晰的单一模型类。

- [ ] 先测现有 `FrameTime` 同帧幂等、帧号单调、禁用动效直达；加入停摆恢复、连续改目标、不同帧率和首次显示测试，再设计停摆阈值来源。
- [ ] 为开关等局部状态提供可中断弹性反馈，动画参数由皮肤提供；按下/释放/禁用/取消不改变业务事务合同。避免仅更换颜色而声称手感对齐。
- [ ] 设计页面入场：立即切换业务目标，允许再次输入；同一个进度驱动位置和透明度，逐项延迟只作用可见项；避免页面与行双重平移、阴影被图层裁剪。明确动画期绘制、命中、焦点与裁剪的坐标合同；为滚动不重播、减少动效和中断补行为与帧序列验证。

### 4. 模糊、清晰度与资源生命周期

**候选文件：**`platforms/shared/.../backdrop/BackdropRenderer.java`、`BackdropStyle.java`、独立 shader 和 hidden GL tests；`ui/.../design/atomchat/SkiaDraw.java`；按需扩展图像服务。

- [ ] 对当前 Lib 模糊分段计时：状态保护、捕获、滤波、合成及关闭分开计；记录设备、驱动、区域、热身、CPU 提交和 GPU query。旧 64×64 CPU 中位约 6.2ms 不是游戏帧耗时。
- [ ] 不恢复 AtomChat 已撤销的 `BlurMotionGate`：交接记录其隔帧复用背景导致转视角拖影，当前 `boolean full = true` 有对应回归守卫。任何刷新缓存策略须用运动背景实测，不用旧注释推断已启用节流。
- [ ] 增加可选亮度上限前，先有亮/暗背景和源 alpha 两组 GPU 读回测试；目标 alpha、区域外像素和其他 FBO 状态保持不变；shader / 资源失败时验证实底回退。HUD 来源和目标由宿主明确传入；Gnetum 的具体图层 ID 和反射兼容留 AC。
- [ ] 检查 `SkiaDraw.BLUR_FILTERS` 淘汰和关闭所有权，验证 paint 是否仍引用 filter 后再释放；统计原生资源，禁止简单 `clear()` 视为已释放。
- [ ] 图片降采样先测大/小倍率、普通图与像素图、首次成本、缓存命中、源释放、淘汰与重载。单图超过总预算和多图跨预算各测试返回图像可用性，弱引用死亡后验证条目与派生资源清理；区分缓存自有对象与宿主借用对象。再决定阈值；保留宿主选择最近邻等采样方式。现有 AtomChat `ImageQualityTest` 的 `release` 只断言计数和源可用，未直接断言派生图已关闭；字符串守卫也只覆盖特定 rounded 调用，不能证明所有原始图片绘制路径已拦截。
- [ ] 对设备像素密度建立单一变换所有权，针对不同 guiScale 测绘制和输入；描边宽度、相位和动画平移分别测，不把“所有填充边缘必须对齐”作为结论。
- [ ] 若后续测量表明 AtomChat 点阵确为热点，先对原实现、分 alpha 批次和离屏缓存分别测绘制时间、首次构建与内存。缓存键至少核对尺寸、圆角、方向、颜色/透明度、密度、裁剪及资源代际；主题、缩放、resize、reload 和关闭均测失效与资源释放，并对齐原图像与用户观感。方案只定义验证，是否优化 AtomChat 另行授权。
- [ ] 重建可重复离屏性能夹具，至少对 50 / 500 条消息、静止 / 滚动、冷 / 热缓存、模糊开 / 关分别记录；比较平均帧间隔、渲染线程 CPU 及分配量，GPU 时间单列，保留版本、输入、命令和原始结果。真实游戏由用户操作，结果作为独立一层证据。
