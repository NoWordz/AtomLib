# AtomLib 物品图标诊断与验收方案

> 状态：讨论后的待确认方案。本文只规划，不代表已经执行、批准实现或完成实机验收。实施前先让用户确认；按本次会话约定选择执行方式，不自动启用协作工作流。

**目标：** 找出物品图标候选的主要成本，依据证据决定修复，在 Fabric 1.21.1 的真实物品选择弹窗完成用户手动验收。

**方法：** 先保留现有候选和原始证据，拆分无 Minecraft 的合成 GL 路径并测量探针本身的干扰；再根据数据提出具体优化与失败降级设计。试用工程提供可关闭的本地诊断和真实原版动态物品样本，由用户在现有测试实例中操作。三端自动验证与 Fabric 实机结果分别报告。

**技术环境：** AtomLib 公共模块 Java 17；Forge 1.20.1/JDK 17、Fabric 1.21.1/JDK 21、NeoForge 1.21.1/JDK 21；既有 Skija、GL、Yoga 与独立 CreatorTrial。保持现有依赖版本。

## 已确定的边界

- 本轮首要场景是偶尔打开的物品选择弹窗，按实际可见数量记录负载；不是常驻 HUD 或大规模背包的性能承诺。
- 原版模型、附魔闪光、时钟和指南针需要随时间及游戏状态正确变化；首版不要求数量、耐久条和原版 tooltip。
- 单个物品绘制失败时，目标是该项有占位、记录平台/物品 key/原因，其他选择操作尽可能可用；如果状态无法安全恢复，停止相关绘制并报告，不能吞掉致命错误或宣称一定可继续。
- 优化路线由分段数据决定；暂不预选缓存、删状态保护或降低刷新频率。模糊性能单独排期，本轮不优化。
- 首轮由用户在自己现有的 Fabric 1.21.1 实例手动操作；不自动启动游戏、下载游戏资源或部署。具体实例路径及安装方式在准备验收时由用户指定。
- Fabric 实机验收后阶段收口；Forge 和 NeoForge 补齐本轮改动影响到的构建及自动验证，不把它们写成实机通过。本地候选留存，不推送、发版、升版或改 AtomChat 输入锁。
- 性能用同机同场景数据和用户体感共同判断；不预设合格毫秒数，不把 CPU 提交时间、GPU 时间和完整帧时间当成同一指标。

## 当前依据与未知数

- 本地 `c3188d4` 已实现模态、三端图标离屏适配和试用入口；[独立复核](../../evidence/modal-item-icons/review.md)记录了 UI 97 项、Fabric 图标相关 7 项、消费者 9 组实跑范围，真实 MC 未跑。
- [原探针](../../../platforms/shared/src/test/java/com/atom/lib/client/render/item/ItemIconHiddenGlTest.java)使用 16 个 32px 合成图案，计时包住 `prepare` 和 `close`，每轮随后同步读取 GPU query。query 等待发生在当轮 CPU 计时之外，但会影响后续迭代的队列和节奏，因此需要单独对照；不能认定它就是 9–10ms 的原因。
- [ItemIconAtlas](../../../platforms/shared/src/main/java/com/atom/lib/client/render/item/ItemIconAtlas.java)包含布局、预 flush、状态捕获、容量检查、清理、原生 pass、图像导入及关闭时 flush。`withContext` 自身也使用状态保护；这些只是待测环节，不是已证实瓶颈。
- `D:/AtomLib-CreatorTrial/src/main/java/dev/creatortrial/TrialScreen.java` 当前每帧由 ID 新建普通 `ItemStack`，现有 24 项不含时钟、指南针或附魔样本；完成本轮验收必须补真实测试数据，不能用静态图片替代。

## 任务 1：复现并拆分合成 GL 成本

- [ ] 检查 Lib/CreatorTrial 工作区、候选身份和现有证据；记录源码提交、JDK、GPU、驱动、窗口上下文、测试版本及当前系统负载。保护原候选、锁与历史证据。
- [ ] 在独立 hidden GL 诊断中沿用同一组 16×32px 图案及 `prepare`/`close` 总计时；分别记录请求与图块构造、前置 flush、外层状态 capture/restore、容量增长、清空与像素状态归一、pass、借图导入、帧构造、close/后置 flush。嵌套计时须标注父子关系，不能把重叠时段相加当总耗时。
- [ ] 分开首帧/扩容与稳定复用，记录容量和分配次数；相同场景分别做无 GPU query、延迟检查 query 可用状态、原同步取结果三组。不可用结果标记 unavailable，禁止为获得数据而增加 `glFinish` 或在热路径等待。
- [ ] 增设可重复的单区段/空 pass 对照，执行预热后记录原始样本、中位数和 p95、样本数与时序；至少重复三轮，并注明系统负载。计时开关关闭/开启也做对照，量化插桩开销。合成图案结果始终标注非 MC 物品。
- [ ] 维持现有图像方向、透明边缘、PBO、资源借用有效期、状态恢复与异常重试的回归。新增插桩须在关闭时不改变资源所有权和渲染结果。
- [ ] 执行 Fabric 原有图标 hidden GL 回归，并将新探针单独放入新的证据目录。既有命令示例（JDK21，Fabric 工程）：

```powershell
cd D:/AtomLib/platforms/1.21.1-fabric
$env:JAVA_HOME='C:/Program Files/Java/jdk-21.0.11'
.\gradlew.bat hiddenGlTest --tests 'com.atom.lib.client.render.item.*' --rerun-tasks --offline --no-daemon --console=plain -PatomlibRenderEvidence=D:/AtomLib/build/item-icon-diagnostics-20261102/fabric-gl
```

**交付：** 每段成本及测量干扰的报告、原始样本和可复现命令；解释不了的部分明确保留为未知。若环境或命令不适配，记录实际错误，不用缓存任务冒充实跑。

## 任务 2：数据驱动决策、失败隔离与回归

- [ ] 根据任务 1 的数据提出具体瓶颈、证据、预计收益、正确性风险和最小修复；如涉及长期图标缓存、新渲染架构或更改公共合同，先呈交方案并取得用户确认。数据不足时先准备实机诊断，不为追数字盲目改实现。
- [ ] 对可证实且不改变架构的局部改动，先构造能够重现问题的行为或性能对照，再实现；保持动态 ItemStack 内容按当前帧和游戏状态更新。状态保护、flush、context 生命周期必须以实际依赖证明后才能收缩；不得以删保护换跑分。
- [ ] 检查现有 `MinecraftItemIcons.prepare` 与 `VanillaItemPass` 的异常路径：区分可恢复的单项失败和全局状态/资源失败。先设计占位数据与日志如何跨过批次；仅在证明该项失败后 framebuffer、批次、矩阵、GL 与 RenderSystem 状态可恢复时继续其他项目。不能捕获 `Error` 后继续当作普通失败；不能用异常触发的伪图像冒充物品。
- [ ] 先构造失败注入：一个物品失败、其他物品仍可选且日志含平台和 key；无法恢复的失败停止该帧且清理句柄；再次打开/重试无悬挂捕获或旧图。纯 GL/合成 RenderSystem 测试各自注明覆盖范围，真实状态由 Fabric 实机验证。
- [ ] 对前后结果使用同机器、同版本、同数据和同诊断设置比较；记录冷/热、分配、p50/p95、样本数与功能测试。仅测量改善不代表实机或其他 GPU 通过。

**交付：** 修复方案与理由、失败处理合同、回归和同条件比较；若没有证据支持安全修复，说明原因并保留未完成项。

## 任务 3：试用工程与可关闭诊断

- [ ] 保持用户原有 24 项业务样本和焦点/分类回归；新增唯一 key 的真实原版附魔物品、时钟、指南针样本。构造真实带附魔状态的 `ItemStack`，不只贴附魔外观；分别验证条目与请求对应，并保留列表滚动和选择操作。
- [ ] 先检查已有计时能力。若不足，在 CreatorTrial 添加默认关闭的本地诊断开关和有限内存样本缓冲，仅在用户主动开启后输出汇总；记录可见图标数、像素尺寸、场景/模糊状态、图标 `prepare`、`close`、页面绘制 CPU 区间和完整帧间隔。不要逐帧刷日志、采集聊天/世界内容、发送网络请求或将调试输出混进普通产品交互。
- [ ] “完整帧间隔”须从同一 Minecraft 客户端帧边界连续采样，覆盖弹窗关闭和开启两种状态；不能把 `TrialScreen.render` 耗时或它自身的调用间隔写成完整游戏帧时间。先核对 Fabric 1.21.1 已解析映射及安全接线点；若无法可靠取得同一边界，就使用用户已有帧时间工具并明确该项缺测，不伪造数据。帧间隔包含帧率限制、VSync 和其他等待，记录这些设置。
- [ ] 对无图标状态与相同镜头、分辨率、模糊设置、帧率上限/VSync、相同场景下的弹窗状态分开采样；各记录预热、样本数、中位/p95。先比较诊断开/关的体感与帧数据，明显干扰时说明限制。不得将两状态差值直接归因于图标：页面布局、模糊和其他界面工作也会变化。
- [ ] 增加轻量自动验证：关闭诊断不产生样本或输出；开启/停止按预期写一次汇总；缺样本不报假绿；每类动态样本确实进入真实请求；不改变现有输入/焦点路径。原 `build trialChecks` 继续全绿，实际数目按结果记录。
- [ ] 生成新的隔离 Maven 候选与 CreatorTrial 包，使用单一输入锁核对实际 Fabric JAR 的 SHA-256；同时记录三端 JAR、试用 JAR、源码快照、构建命令及前后依赖。不能将新样例配旧 beta3 或旧候选锁。

## 任务 4：三端自动验证与用户手动实机

- [ ] 按最终改动运行根模块受影响测试、Fabric 图标 hidden GL 和 CreatorTrial `build trialChecks`；Forge、NeoForge 分别运行受影响的图标 hidden GL、构建/验包与对应独立消费者。改动范围扩大时补相关测试；区分实际执行、缓存和跳过。保持三端各自 JDK/wrapper，并让每次 GL 输出指向独立目录。
- [ ] 用户指定现有 Fabric 1.21.1 测试实例路径后，提供待安装文件名、摘要、依赖和冲突检查步骤；由用户自行安装并启动。若后续用户另行要求代理安装，先确认明确目标和该次授权；不操作其他实例。
- [ ] 给用户一份短操作单：固定相机与窗口设置，采集弹窗关闭/开启对照；F8 打开选择页，检查普通方块、物品、附魔闪光、时钟与指南针；切分类、滚动到底、选中/确认/取消、键盘操作；关闭重开并在可操作时做资源重载；观察世界/原版界面是否被污染。
- [ ] 时钟/指南针依赖世界与状态：记录是否处于有效世界、观察时间与条件；无法观察变化即标未验证，不用静态存在证明动态正确。记录单个图标失败及重试结果，若出现崩溃或状态污染，停止继续验收并保留日志。
- [ ] 收集用户体感、截图或日志及诊断汇总；比较相同场景帧间隔与图标 CPU 耗时，记录用户是否认为顺畅。未反馈前实机项目保持待验，不自动代签；错误先定位再修复并重验受影响项。

## 阶段完成条件

1. 合成探针有分段、同步查询干扰对照、原始样本及解释；优化与否均有证据，未知项未被包装成结论。
2. 单项失败降级有相应自动证据，不能恢复时安全中止；动态效果、可见项与资源生命周期未为优化牺牲。
3. 用户在 Fabric 测试实例完成实际物品、输入、重开、资源重载与同场景性能验收，并明确认可体验；不可观察项目逐项标未验。
4. 最终变更影响到的三端构建/自动验证有命令和结果；Forge/NeoForge 实机、其他 GPU、ARM64、特殊模组渲染器及整合包兼容不因离线通过而宣称已验证。
5. 交付本地候选、对应锁与 SHA、诊断报告、实际执行/未覆盖范围；未经进一步授权不推送、发版、部署、启动游戏或改 AtomChat。
