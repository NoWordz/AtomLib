# AtomLib 与 AtomChat 渲染性能实施方案

**目标：** 用可重复的分段证据定位并减少图标和聊天面板的开销，保留绘制、输入和资源生命周期语义。

**基线：** AtomLib `fba83a0`；AtomChat `ebd74346`。工作前重新核对状态，保留任何并行改动。两个项目分别测量，不把合成 GL 结果称为实际游戏帧时间。

**约束：** 三端 Forge 1.20.1、Fabric/NeoForge 1.21.1；不自动启动游戏、不部署、不发布、不提交。测试产物写唯一的 `build/render-perf-20261104/` 子目录；hiddenGlTest 必须显式设置 `atomlibRenderEvidence`，不得覆盖历史记录。AtomChat 改动限性能诊断及经证据支持的局部修复，保持现有行为和视觉效果。先测试再修复，记录真实执行命令和未覆盖项。

## 1. AtomLib 图标：分段和优化

涉及 `platforms/shared/.../item/ItemIconAtlas.java`、`SkijaRenderBridge.java`、`GlStateScope.java` 和 `ItemIconDiagnosticsGlTest.java`。先阅读 `docs/evidence/item-icon-diagnostics/report.md`，保留现有单活动 frame、有效期、纹理借用、异常恢复和宿主 GL 状态合同。

- [ ] 扩展测试侧诊断，分别测 prepare 的前置上下文、外层状态、清理、导入及 close；细分状态捕获的纹理、UBO 和其他状态，保留父子关系，不相加嵌套计时。覆盖空请求、16 项稳态、扩容和大转小；预热后多轮采样，记录环境、p50/p95、分配和插桩对照。
- [ ] 根据数据只选择可证明的最小优化，例如上下文内不变上限的缓存或可证明等价的受保护内部调用复用；不得无证据缩减状态覆盖、删除 flush、跨帧缓存动态物品。真正空请求可独立考虑快路径，但必须保留 frameId、单活动 frame、透明占位和过期检查。
- [ ] 先编写行为回归：污染纹理/UBO/PBO 等状态、正常和异常退出恢复、纹理生命周期、空项、扩容及旧帧失效；观察旧实现对新增行为或检测实际缺陷的红灯。实施后重新执行回归及同环境 A/B，记录收益和噪声，不设未经证据支持的达标线。无法证明安全或收益时保留原实现并说明。
- [ ] 用独立目录执行三端相关 hiddenGlTest、对应构建与制品检查；验证图标方向、透明边缘、动态内容合同；真实 MC 模型、mod 兼容和性能仍需游戏验收。

## 2. AtomChat 面板：诊断先行、证据驱动修复

基于 `D:/AtomChat-Main`：`shared/.../diagnostics/FrameProfile.java`、`shared/.../render/DotTexture.java`，以及各端 `AtomChatScreen`、`SkiaGraphics`、`ItemIconRenderer`、`PanelBlurRenderer`。阅读 `docs/verification/2026-11-02-render-quality-and-caching.md`，不要重复实现已有缓存。

- [ ] 利用已有诊断机制增加默认关闭、分配有界且非逐帧写盘的分段：原版预处理、模糊、图标准备、绘制、点阵、列表；计数资源重建与冷缓存。使用同一帧 ID 的墙钟样本、限定环形缓冲并一次汇总；明确它不是纯 CPU 时间。验证开关关闭时语义不变、样本配对、上限及汇总。
- [ ] 不启动游戏的条件下建立可重复离屏对照：实际点阵绘制在不同尺寸/密度、图标请求空与非空、冷暖缓存；记录 p50/p95、环境、场景、结果与局限。旧面板总耗时和旧模糊探针不能单独证明根因。
- [ ] 只对独立测量显示有收益且保持视觉/生命周期正确的局部路径修复；点阵可考虑按透明度批量绘制或有界缓存，图标优先研究复用 FBO/深度附件并保留纹理释放与动态模型。先有针对性的失败回归，覆盖尺寸、透明度、颜色、主题、失效/释放、正常及异常恢复；进行像素或行为 A/B 与性能 A/B。没有足够证据则仅交付诊断并列明阻塞，不宣称已修复掉帧。
- [ ] 同步受影响平台实现，运行相应离屏测试、三端必要构建及目标一致性检查；不把离屏结果写成游戏 FPS 验收。
